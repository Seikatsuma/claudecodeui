# Claude UI для компьютера (Mac, Windows) — ветка desktop-app, с 25.09.26

Егор 25.09: тот же интерфейс, что cc.sobsila.ru, но программой на компьютере; Claude работает с
файлами этого компьютера, как Claude Desktop; внутри — наши мозги (без личной памяти и серверных
правил); вход аккаунтом со второго сервера; любой может зарегистрироваться; узкое окно — панель уезжает.

## Как устроено
- Основа — настольная обёртка исходного проекта (CloudCLI, `electron/`), переделанная:
  - `electron/cloud.js` — аккаунт: вход/регистрация почтой прямо в программе → сервер аккаунтов
    **cc2.sobsila.ru/desktop** (второй сервер, `~/desktop-accounts`, там `agent.md`). Ключ устройства
    шифруется системным хранилищем. Серверы владельца приходят оттуда же и открываются вкладками.
  - `electron/localServer.js` — свой сервер интерфейса всегда (не цепляться к чужому на компьютере),
    Claude — вложенный в пакет `@anthropic-ai/claude-agent-sdk-<система>-<процессор>` (CLAUDE_CLI_PATH).
  - `electron/localAuth.js` — второй вход (в локальный интерфейс) программа делает сама: пользователь
    в своей базе `<userData>/local/claude-ui.db`, вход подкладывает `preload.cjs` до загрузки страницы;
    мастер первого запуска (Git, агенты) отмечается пройденным.
  - `electron/brains.js` — мозги: `<userData>/brains/current` = вложенная `desktop/brains` или новее
    с сервера аккаунтов (версия в `manifest.json`, сравнение строкой ГГГГ.ММ.ДД-N).
  - `electron/main.js` `getServerEnv()` — режимы общего сервера (OPEN_REGISTRATION, .claude-webuser-N,
    второй блок, голос) выключены явно; владелец (тариф owner) — чаты без вопросов, как на сайте.
- Мозги в работе Claude — `server/modules/providers/list/claude/desktop-brains.js` (включается только
  при CLAUDE_UI_BRAINS_DIR): правила → добавка к системным, `protocol.md` → к каждому сообщению,
  `plugin/` → 21 помощник и 8 навыков, защита от удаления → перехватчик PreToolUse (Bash|PowerShell;
  после «да» — префикс USER_CONFIRMED=da). Перехватчики внутри процесса: на Windows нет bash/python.
  Папку `~/.claude` человека не трогаем — его правила и вход в Claude остаются его.
- `desktop/brains/CLAUDE.md` — в git только благодаря `!desktop/brains/CLAUDE.md` в .gitignore (общее правило
  `CLAUDE.md` его прятало: сборки GitHub до 28.09 шли без правил → `getBrainsDir()` = null → мозги выключены
  целиком, а сервер не отдавал их при той же версии). Теперь `syncFromServer` берёт мозги и при той же версии,
  если в рабочей копии нет CLAUDE.md. Мозги кнопкой «Обновить» НЕ едут (их нет в пакете начинки) — новая
  версия доезжает с сервера аккаунтов при входе: поднять `version` в manifest.json → `publish-brains.sh`.
- Подключения и возможности (28.09.26, Егор: «написал „хочу подключить Google“ — и он такой: да»): навыки
  `plugin/skills/connect` (лестница: подключения аккаунта claude.ai → папка облака → MCP по адресу с входом
  через инструмент `mcp__<имя>__authenticate` → MCP с ключом → свой скрипт/браузер; ключи — Связка ключей Mac /
  `~/.claudeui/keys.env` Windows) и `plugin/skills/tools` (uv без администратора, `scripts/photos_info.py` —
  дата/место/адрес фото с HEIC, `scripts/video_frames.py` — кадры, дата, место, звук; ffmpeg из imageio-ffmpeg).
  `claude mcp login` и `/mcp` во встроенном Claude 2.1.165 нет — вход в MCP только тем инструментом.
  `applyDesktopBrains` добавляет в PATH Claude `~/.local/bin` и `~/.claudeui/node(/bin)` — туда ставятся uv и Node.
- Узкое окно — `src/components/app/AppContent.tsx`: 768–1023 точки → полоска значков, панель выезжает
  поверх чата; уже 768 — телефонная раскладка. Окно сжимается до 420 (`desktopWindow.js`).

## Обновление без установщика (28.09.26, Егор: «чтобы обновления выкатывались сами — кнопка, нажал и обновилось»)
- Обновляется начинка — dist, dist-server, public, shared (+ package.json, update-build.json), 10 МБ против 240–290 МБ
  установщика. Оболочка (electron/) и пакеты (node_modules, с Claude) — из установки: полное самообновление на Mac без
  платной подписи Apple система не пропускает. `electron/appUpdate.js`: `<userData>/app-update/builds/<номер>`
  (node_modules — ссылка/junction на пакеты установки), `current.json` — рабочая и прежняя, bad-builds.json — не
  запустившиеся. Работающую папку не переименовываем и не удаляем (на Windows не выходит, пока сервер жив) — подмена
  одним файлом-указателем; уборка остатков — `cleanup()` при запуске, до сервера.
- Номер сборки = `github.run_number` (CLAUDEUI_BUILD → update-build.json в корне программы). depsHash — отпечаток
  package-lock.json (`scripts/release/claudeui-update-meta.mjs`): не совпал — кнопка «Новая версия» ведёт на страницу
  скачивания. Сборка на своей машине (без номера) обновления не проверяет.
- Цепочка: пуш в desktop-app → `update-pack` (ubuntu: подготовка STAGE_ONLY + `pack-claudeui-update.mjs`) → проба на 7
  системах ставит пробную начинку (номер +1000000) поверх установленной (SMOKE_UPDATE_DIR, CLAUDE_UI_UPDATE_AUTO_INSTALL) →
  `update-publish` выкладывает выпуск `desktop-update-<номер>` → сервер аккаунтов забирает его сам (`update-mirror.py`,
  крон 10 мин) → программа видит его на `/desktop/api/app-update` (при запуске и раз в час) → кнопка «Обновить» в верхней
  полосе (и «ВЕРСИЯ» в настройках) → вопрос → скачать, сверить sha256, распаковать рядом, остановить сервер, подменить
  папку, запустить сервер, перезагрузить вкладку. Не поднялась новая начинка — сервер сам запускается из установки.
- С GitHub программа не качает: из сетей людей он часто медленный (см. useVersionCheck.ts).
- Правки сайта (main) доезжают, только если влиты в desktop-app; правка electron/ или пакетов — только новым установщиком.

## Подписки Claude владельца (27.09.26, Егор: «перенеси мои подписки сюда, не хочу через настройки»)
- Ключ сервера не копируем (при продлении старый гаснет — вход на сервере слетит, 12.09). Вместо него —
  годовой ключ `claude setup-token` (отдельный, под другое устройство): выпуск в чистой папке
  (CLAUDE_CONFIG_DIR=/tmp/…), хозяин подписки один раз жмёт «Разрешить» в браузере и отдаёт код.
- Хранится на сервере аккаунтов (таблица claude_tokens, `manage.py add-claude <почта> <почта-Claude> < ключ`),
  выдаётся только тарифу owner: `GET /api/claude-accounts`. Программа (`cloud.refreshClaudeAccounts`, до
  запуска сервера этого компьютера, не дольше 6 с) хранит их зашифрованными рядом с ключом устройства,
  отдаёт серверу одной переменной CLAUDE_UI_CLAUDE_ACCOUNTS; `server/modules/user/desktop-claude-accounts.ts`
  убирает её из окружения и кладёт активный в CLAUDE_CODE_OAUTH_TOKEN (каждый запуск Claude берёт
  окружение заново → переключение со следующего сообщения). Выбор — значок внизу боковой панели
  (тот же /api/user/owner-accounts, что на сайте), запоминается в `<userData>/local/claude-account.json`.
  Нет подписок — Claude работает под собственным входом человека, как раньше. Новые ключи — со следующего запуска.
- «<synthetic>» на кнопке модели: так Claude помечает свои служебные записи (ошибка входа, прерывание);
  при поиске модели чата они пропускаются (claude-models.provider, provider-models.service).
- Значок экрана входа — logo-256.png (было 32 точки при показе 48 → квадратики на Retina).

## Доступ к файлам и подтверждения (26.09.26, как в Claude Desktop)
- Папка проекта — системным окном («Открыть папку» → «Выбрать папку…»: `claudeui:pick-folder` в main.js,
  мост `window.claudeUiDesktop` в preload.cjs, `src/lib/desktopBridge.ts`, мастер `project-creation-wizard`).
  Любая папка, кроме системных (`validateWorkspacePath` при CLAUDE_UI_DESKTOP=1 не держит в домашней).
  После выбора сразу новый чат в папке (Sidebar.handleProjectCreated).
- Новый чат — режим «Спрашивать» (DEFAULT_PERMISSION_MODE=default). Режимы и описания — `claudeModes` в
  ru/en chat.json, порядок как в Claude Desktop (ComposerPermissionMenu). Название режима видно на кнопке.
- Окно разрешения: PermissionRequestsBanner + describePermission.ts — вопрос человеческим языком, файл или
  команда, для правки — что уберётся/добавится, опасное — красным. «Разрешать всегда» только для простой и
  не опасной команды (составная «cd … && rm» давала бы правило Bash(cd:*) на всё). «Запретить» — сразу;
  «Запретить и подсказать» — пояснение уходит Claude. Окно ждёт ответа сутки (CLAUDE_TOOL_APPROVAL_TIMEOUT_MS;
  на сайте 55 с — запрос отклонялся сам).
- Мозги: в «Спрашивать»/«План» защита от удаления не стопорит (подтверждает окно), Claude не просит «да» в
  чате; в остальных режимах — «да» текстом и USER_CONFIRMED=da. Режим подкладывается к каждому сообщению.

## Вход в подписку Claude из чата, без терминала (28.09.26)
Егор 28.09: «чтобы пользователи быстро разобрались, что привязывать и что нажимать; в чате само всё предлагало; без терминала — как iPad, которым пользуется ребёнок».
- Сервер: `server/modules/providers/list/claude/claude-desktop-login.ts` запускает вложенный Claude `auth login --claudeai`:
  он сам открывает браузер, после «Разрешить» ответ приходит на localhost этого компьютера. Запасной путь — страница с
  кодом: код из карточки пишется в стандартный ввод. Адреса `/api/providers/claude/desktop-login[/start|/code|/cancel]`,
  только при CLAUDE_UI_DESKTOP=1 (на сайте браузер открылся бы на сервере). Таймаут 10 минут; выход программы гасит вход.
- Вошёл ли Claude — `claude auth status --json` (почта, подписка), а не файл `.credentials.json`: на Mac вход в
  «Связке ключей», файлом его не видно (настройки показывали «не вошли» при живом входе). Запас 10 с, `?fresh=1` — без него.
- Интерфейс: `src/components/provider-auth/claude-connect/` — одно состояние на страницу (claudeConnectStore) и карточка
  (ClaudeConnectCard): над полем ввода чата, пока Claude не подключён (видна до первой ошибки), и в «Настройки → Агенты →
  Claude» вместо терминала. «/login» в чате не уходит Claude, а открывает карточку. «Not logged in…» в ленте — одна русская
  строка (MessageComponent). Пустой чат пишет «Сначала подключите Claude», а не «Claude готов».
- Всё это — в dist/dist-server: приезжает кнопкой «Обновить», новый установщик не нужен.
- Проба на Linux: настоящий Claude без входа (браузер открыт с localhost-возвратом, неверный код → «Код не подошёл»)
  и пробная замена CLAUDE_CLI_PATH, отвечающая «вошли» (карточка «Готово — Claude подключён», настройки «Подключен»).
  Настоящий вход в подписку на Mac проверяет человек.

## Сборка и проверка
- `.github/workflows/claudeui-desktop.yml` — .dmg для Mac на M и на Intel, установщик Windows, проверка на 7 системах; пуш в
  `desktop-app` или вручную. `scripts/release/build-claudeui-desktop.mjs` кладёт сервер со всеми
  пакетами внутрь (нативные пересобраны под Electron), `smoke-claudeui-desktop.mjs` запускает
  собранную программу там же, входит пробным аккаунтом (секреты CLAUDEUI_SMOKE_*; аккаунт
  smoke-ci@claudeui.test) и снимает экран → артефакты smoke-*.
- Здесь (Linux, без экрана): Xvfb и GTK распакованы без sudo в `/tmp` (см. историю 25.09), Electron
  через Playwright; в пробе окружение чистить — чат наследует настройки сайта (OPEN_REGISTRATION и т.п.).
- Версия программы = версия интерфейса (`package.json`): иначе интерфейс покажет ложное «обновление установлено — перезапустите сервер».

## Грабли
- Программа уходит людям: сборка вырезает комментарии (esbuild, только пробелы) из сервера, обёртки и страницы,
  не кладёт тесты и `desktop/agent.md`, правит правила сайта владельца (`STAGE_PATCHES`) и останавливается, если
  страж находит имена/служебные адреса (`PERSONAL`). Новое личное в коде — сборка упадёт, это задумано.
- Защита от удаления — любое удаление (rm, del, Remove-Item, unlink, из Python/Node, сброс правок git);
  команды оболочки сверяются с текстом без кавычек. Ловит команды, а не намерения: основа — правило в CLAUDE.md.
- Mac подписан «для себя» (ad-hoc): при первом открытии — правой кнопкой → «Открыть» (или Настройки →
  Конфиденциальность → «Всё равно открыть»). Windows без подписи: SmartScreen → «Подробнее» → «Выполнить
  в любом случае». Настоящие подписи — платные (Apple Developer ~$99/год, сертификат Windows).
- Обёртка CloudCLI сжимала страницу дважды (setAutoResize + resize) — оставлен только resize.
- Список чатов — только разговоры, начатые человеком (журнал `~/.claude/history.jsonl`); чаты ботов скрыты.
- Claude на Windows без Git for Windows работает через PowerShell (документация Claude Code).
